# Iconize · 文件图标

最低需要 **NoteGen 0.37.1**，并满足 `plugin.json` 声明的插件 API 版本。

[English](README.en.md)

通过 NoteGen 公开 `fileIcons.setRules()` 接口，为文件树和标签页设置一致的内置图标或 Emoji。插件无网络请求，不读写笔记正文。

- 文件与文件夹独立指定图标，右键菜单直接带入相对路径。
- 精确路径、扩展名与默认规则；最多 100 条，可编辑、停用、删除和拖拽排序。
- 优先级固定为：指定图标 → 精确路径 → 扩展名 → 默认；同组首条匹配生效。拖拽后会重新按组排列。
- 配置存储在 `storage.workspace`，启动时恢复；使用宿主的有界图标缓存，更新规则会失效缓存。停用、失败、卸载由宿主移除运行时规则。
- 可选 `notes.list` 权限用于接收授权文件夹内的笔记移动/删除事件。只有开启“跟随移动”的文件指定图标才随事件更新。

详细操作见 [中文使用说明](USAGE.zh-CN.md)。初次启用不添加默认规则，不改变已有图标。

## 当前接口边界

本实现已读取当前本地 SDK 及宿主源码，不依赖宿主私有模块。依赖公开协议 `^0.1.4`（本地未发布设置视图协议），清单应用版本下限 0.37.1；发行版还需要实际包含新资源接口，版本号本身不能替代兼容性验证。

`PluginFileIconRule` 仅有 `kind/path/extension/icon`，校验器拒绝额外字段；`icon` 仅接受 `{name}` 或 `{emoji}`。因此**不支持独立设置图标颜色**，界面明确提示并提供彩色 Emoji；没有保存无效颜色，也不注入 CSS 或自定义 SVG。

路径匹配是工作区相对路径的精确匹配，不支持 glob、目录前缀或递归继承。路径遵循 SDK 的资源路径校验（240 UTF-8 字节、最多 12 层，以及保留目录、文件类型等限制）；部分实际存在的文件路径因此不能单独指定图标。可在可用时改用扩展名规则。

`notes.onDidChange` 不是通用文件系统事件流。文件夹、非笔记附件、外部工具重命名、插件关闭期间的变更，以及权限边界外的移动均无法保证身份跟随。固定路径规则始终留在原位置，手动编辑路径可重新绑定。授权范围内删除事件会移除开启跟随的文件指定规则；跨授权边界移动可能被宿主转换为删除，插件不会推断隐藏目标。重复移动事件不会重复迁移。

没有跨窗口 storage 订阅或 compare-and-swap 接口。每次修改前重新读取配置，同一实例内事件与操作串行执行；其他已打开窗口需使用“重新载入并应用”或重启插件刷新。避免同时在多个窗口修改规则；跨窗口同时写入仍可能最后写入者覆盖。跨插件冲突按宿主的插件 ID 字典序决定，Iconize 的指定图标不能覆盖排序更靠前插件已命中的规则。

## 开发与集成

沿用仓库 `shared/workbench.ts` 的声明式 UI、双语文案、工作区守卫及错误通知，不重复实现宿主 UI。开发依赖为 `@notegen/plugin-api: workspace:^`、`@notegen/plugin-cli: workspace:^`、`typescript: ^5.8.3`；无运行时第三方依赖。现有 workspace 通配符已包含本目录。

仅在获得授权后安装/构建：`pnpm --filter @notegen/plugin-iconize build`；打包命令为 `pnpm --filter @notegen/plugin-iconize plugin:pack`。SDK CLI 自动收集 `USAGE.md` 和 `USAGE.zh-CN.md`。构建依赖 SDK 已生成的新协议产物；设置页迁移后已重新构建 SDK 和插件。

后续统一集成需更新根中英文 README、`market/registry.json`，并统一生成 `pnpm-lock.yaml` 的 importer。根 package.json 无需新增依赖。本轮不修改这些共享文件，不提交、推送或发布。
